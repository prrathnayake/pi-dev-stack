# Pi Dev Stack

A Raspberry Pi self-hosted developer, AI, automation, monitoring, and remote-access stack.

This project is designed for a Raspberry Pi 5 homelab/cyberdeck setup using Docker Compose and free temporary Cloudflare Tunnel URLs.

## Included Services

### AI and Automation

| Service | Purpose | Local URL |
|---|---|---|
| n8n | Workflow automation | http://localhost:5678 |
| Ollama | Local LLM runtime | http://localhost:11434 |
| Open WebUI | Web UI for Ollama | http://localhost:3000 |

### Data Services

| Service | Purpose |
|---|---|
| PostgreSQL | n8n database |
| Redis | Cache / queue-ready service |

### Management and Monitoring

| Service | Purpose | Local URL |
|---|---|---|
| Portainer | Container management dashboard | http://localhost:9000 |
| Dozzle | Real-time Docker logs | http://localhost:9999 |
| Uptime Kuma | Service uptime monitoring | http://localhost:3001 |
| Homepage | Central dashboard launcher | http://localhost:8088 |
| Glances | System CPU/RAM/network monitor | http://localhost:61208 |

### Remote Access

| Tool | Purpose |
|---|---|
| cloudflared | Temporary public HTTPS URLs using trycloudflare.com |

## Local Customization Without Git Conflicts

Do not modify tracked infrastructure files directly:

- docker-compose.yml
- setup.sh
- tunnel.sh
- validate.sh
- stop.sh

Instead use local override files.

### Git-safe local files

These paths are ignored by Git:

```text
.env
.env.local
local/
data/
logs/
homepage/
docker-compose.override.yml
```

This prevents future `git pull` conflicts.

### Local Docker overrides

Create:

```bash
cp docker-compose.override.example.yml docker-compose.override.yml
```

Docker Compose automatically loads it.

Example:

```yaml
services:
  open-webui:
    environment:
      WEBUI_NAME: Pasan AI Lab
```

### Local scripts

Store custom scripts inside:

```text
local/
```

Example:

```text
local/custom-backup.sh
local/custom-tunnels.sh
```

## Quick Start

```bash
sudo apt install -y git

git clone https://github.com/prrathnayake/pi-dev-stack.git
cd pi-dev-stack
chmod +x setup.sh stop.sh tunnel.sh validate.sh
./setup.sh
```

If Docker permission fails after install, run:

```bash
newgrp docker
```

Then rerun:

```bash
./setup.sh
```

You can also use sudo:

```bash
sudo ./setup.sh
```

## Stop the Stack

Stop containers and Cloudflare tunnels:

```bash
./stop.sh
```

Stop and remove Docker volumes:

```bash
./stop.sh --volumes
```

Full reset, including local `data/` and `logs/` folders:

```bash
./stop.sh --wipe-data
```

## Validate the Stack

```bash
./validate.sh
```

## Get Public Cloudflare URLs

Temporary public URLs are generated by `tunnel.sh`.

Check all tunnel URLs:

```bash
grep -R "trycloudflare.com" logs/
```

Or inspect logs manually:

```bash
cat logs/n8n.log
cat logs/open-webui.log
cat logs/portainer.log
```

Important: free `trycloudflare.com` URLs are temporary. They stay alive only while the `cloudflared` process is running. If the Pi restarts or the tunnel stops, the URL changes.

## Portainer First-Run Timeout

If Portainer says:

```text
Your Portainer instance timed out for security purposes.
```

Restart Portainer:

```bash
docker restart pi-portainer
```

Or with sudo:

```bash
sudo docker restart pi-portainer
```

Then open Portainer immediately and create the first admin user.

## n8n Permission Fix

If n8n logs show:

```text
EACCES: permission denied, open '/home/node/.n8n/config'
```

Run:

```bash
sudo chown -R 1000:1000 data/n8n
docker compose restart n8n
```

Or do a full reset:

```bash
./stop.sh --wipe-data
./setup.sh
```

## Docker Permission Fix

If you see:

```text
permission denied while trying to connect to the docker API at unix:///var/run/docker.sock
```

Run:

```bash
newgrp docker
```

Or logout and log back in.

For immediate use:

```bash
sudo docker compose up -d
```

## Cloudflare Tunnel Notes

This project uses free quick tunnels:

```bash
cloudflared tunnel --url http://localhost:5678
```

These do not require a paid domain or Cloudflare account, but URLs are not permanent.

For production, use one of these:

- buy a cheap domain and connect it to Cloudflare
- use DuckDNS / No-IP / EU.org
- create a named Cloudflare Tunnel
- add Cloudflare Zero Trust authentication
